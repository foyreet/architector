# Архитектор

Локальная визуальная среда для ML: соберите схему из блоков, запустите на своём
компьютере и изучите результаты. Интерфейс на русском. Регистрация не нужна.

В комплекте: редактор схем, каталог встроенных и собственных блоков, CSV/Kaggle,
Python, локальные проекты и история запусков, метрики и журналы, AI Chat,
пятираздельные дизайн-документы, доска и справочник «Обучение».
Готовых учебных проектов и демодатасетов нет.

## Быстрый запуск

Установите **Python 3.11 или новее** с [python.org](https://www.python.org/downloads/).
На Windows при установке включите «Add Python to PATH».
Скачайте этот репозиторий через **Code → Download ZIP**, распакуйте его и откройте
терминал в полученной папке. Или склонируйте его через Git.

**macOS / Linux:**

```sh
python3 run_local.py
```

**Windows:**

```powershell
py run_local.py
```

Скрипт сам создаст `.venv`, установит зависимости и откроет **http://localhost:8770**.
Первый запуск требует интернета и занимает несколько минут. Для следующих
запусков используется та же команда, повторная установка не нужна, пока список
зависимостей не изменился. Для остановки нажмите Ctrl+C в терминале.
Все проекты и результаты остаются в папке `data/` рядом с приложением.
Для запуска без открытия браузера добавьте `--no-browser`, для другого порта — `--port 8771`.

Одна кнопка **Сохранить** записывает проект и резервную копию в браузере.
**Запустить** также сохраняет схему перед выполнением. **Создать схему** открывает
пустое полотно. Каталог «+» содержит блоки, ваши проекты и сохранённые данные.
Подсказки по работе находятся в разделе **Обучение**.

Python-блоки выполняются отдельными локальными процессами с правами вашего
пользователя, включая доступ к файлам и сети. Запускайте код, которому доверяете.
Приложение слушает только localhost; аккаунт Архитектора не нужен.

## Своя модель в AI Chat

При первом открытии чат предложит настройку. Без неё схемы и обучение работают.

- **Другая модель**: укажите базовый URL OpenAI-совместимого API, идентификатор
  модели и свой ключ, если нужен. Нужна поддержка `/chat/completions` и вызовов
  инструментов (tool calling). Подойдут совместимые локальные или облачные API.
  Для сервиса на ноутбуке используйте, например, `http://localhost:11434/v1`.
  Саму модель и её API нужно запустить отдельно; приложение их не скачивает.
- **Аккаунт ChatGPT · через Codex**: настройки проверят наличие Codex. Если его
  нет, появятся инструкция установки, команда с кнопкой копирования и
  «Проверить снова». После установки станет доступен вход через ChatGPT.
  Codex не устанавливается автоматически; доступ зависит от вашего аккаунта.

«Сохранить и проверить API» сохраняет настройку и запрашивает `/models`;
сообщение модели не отправляется. Некоторые совместимые API не предоставляют
этот маршрут: можно просто сохранить подключение. После ошибки настройки
сохраняются, их можно исправить. Смена модели доступна через «Настроить AI».

Схема, выбранные документы, фрагменты данных и журналы становятся доступны
выбранному AI при отправке сообщения. Предложения изменений нужно применить
в интерфейсе; AI не запускает обучение автоматически. При использовании
облачной модели переданные сведения уходят её провайдеру.

Настройки AI и ключ API сохраняются локально в `data/workspace/ai/` с правами
владельца файла, без шифрования. Авторизация Codex также хранится внутри папки
данных. Kaggle, Hugging Face и OpenRouter подключаются своими ключами в
«Подключениях»; ключи, введённые там, живут в памяти вкладки. Не публикуйте папку
`data/`, резервные копии или свои `.env`.

## Внешний AI через MCP

MCP даёт вашему внешнему AI-клиенту инструменты Архитектора, а не подключает
модель к встроенному чату. В клиенте, поддерживающем Streamable HTTP MCP,
добавьте адрес **http://localhost:8770/mcp**, без авторизации. Клиент должен
работать на том же компьютере и иметь доступ к localhost. Удалённый облачный
клиент не сможет подключиться напрямую.

Инструменты: справочник, каталог контрактов блоков, список/чтение проектов,
проверка, создание и обновление схем. Выполнение произвольного кода и запуск
обучения через MCP отсутствуют. Подробности: [MCP_GUIDE.md](MCP_GUIDE.md).

## GPU и дополнительные библиотеки

Для встроенного GPU-блока установите `requirements-gpu.txt` в окружение приложения:

```sh
.venv/bin/python -m pip install -r requirements-gpu.txt
```

На Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.
Используется GPU вашего компьютера: CUDA или Apple MPS, если его поддерживает
установленный PyTorch. Без GPU выбирайте CPU/Python-блок. Собственные библиотеки
для Python-блоков устанавливайте через тот же Python из `.venv`.

## Ресурсы и данные

- В один момент выполняется одна схема, следующая ждёт в очереди; максимум два
  незавершённых запуска в локальном рабочем пространстве.
- Время Python-блока — 30 секунд по умолчанию, до 60 секунд в настройках
  блока. Исполнитель отслеживает память процесса и дочерних процессов; при
  превышении 1024 МиБ останавливает их. Порог меняется переменной
  `ARCHITECTOR_PYTHON_MEMORY_MB`. Проверка периодическая: возможен кратковременный
  перерасход. Это не жёсткая изоляция, и общий расход приложения не ограничен
  этим порогом. Встроенные ML/GPU-операции имеют собственные ограничения.
- CSV читается целиком, без произвольного обрезания строк. Это **не потоковое**
  обучение: размер входного запроса, JSON-данных и оперативная память ограничены.
  Строки данных — до 16 МиБ JSON; артефакт/вход-выход Python — до 32 МиБ JSON; мастер CSV — до 2 МиБ текста.
  Большой файл может занимать в RAM существенно больше места.
- Встроенный GPU-протокол ограничен 8 МиБ и рассчитан на небольшие задачи;
  это не универсальный запуск произвольного GPU-кода.
- Для переноса всех проектов, CSV, результатов, документов и истории остановите
  приложение и скопируйте `data/`. Экспорт JSON схемы не включает исходные
  датасеты, модели и ключи. Дизайн-документ экспортируется и импортируется отдельно.

Нет преднастроенного доступа к серверу автора, общего аккаунта, автодеплоя,
Stepik/LTI или облачного каталога сообщества. Доска локальная. Обмен схемами и
дизайн-документами — через файлы. Интернет используется для установки зависимостей
и явно выбранных внешних сервисов. Диктовка зависит от браузерного Speech API.

## Разработка и проверка

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser_local.py
.venv/bin/python tests/browser_ai_setup.py
.venv/bin/python tests/native_smoke.py
```

Тесты создают временные данные; реальные ключи и платные AI-запросы не нужны.
В CI проверяется настоящий локальный Python-блок с обучением scikit-learn.
Для GPU нужна отдельная проверка на соответствующем оборудовании.
